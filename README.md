# pbt-skills

Property-based testing skills for [Claude Code](https://claude.com/claude-code).

Most "property-based" tests generated by LLMs aren't actually property-based — they're tautologies (`assert add(x, 5) == x + 5`), glorified example tests, or self-oracles that reimplement the function under test. These skills enforce the procedure that catches those failures: write the property in English, name the oracle, and reject obvious traps *before* touching a generator.

## What's included

- **`property-based-testing`** — Language-agnostic core. A three-pass discovery workflow (contract → properties → implementation) for finding real invariants, plus sibling modes for designing new code so properties hold by construction and for diagnosing failed property tests. Annotated catalog of anti-patterns and an eight-category property taxonomy with examples in Python, TypeScript, Rust, and Haskell.
- **`pbt-hypothesis`** — Hypothesis-specific (Python). Strategies, `RuleBasedStateMachine`, settings/profiles, and Hypothesis-specific traps. Pairs with the core skill.

Both skills auto-activate when the task mentions properties, invariants, oracles, generators, shrinking, or property-based testing in any form.

## Compared to other PBT skills

Trail of Bits ships a `property-based-testing` skill as part of their security-focused [skills marketplace](https://github.com/trailofbits/skills). Their skill is excellent and broader in scope — it covers Solidity/Vyper smart contract patterns, includes refactoring guidance for hard-to-test code, and detects PBT opportunities proactively in unfamiliar codebases. If you're doing security audit work or want a one-skill-fits-all approach, install theirs.

This skill is narrower and goes deeper on one thing: the discovery discipline — a procedural workflow that forces property reasoning before code generation. Empirically (see `eval/` once it exists), it produces tests with stronger oracle independence and fewer implementation-coupled properties than either no-skill or trailofbits-only outputs, at the cost of less breadth.

The two skills can be installed together; they don't conflict.

## Install

In Claude Code:

```
/plugin marketplace add alialavia/pbt-skills
/plugin install pbt@pbt-skills
```

That's it — the skills become available in every session.

## Layout

```
.claude-plugin/marketplace.json   ← marketplace manifest
skills/
├── property-based-testing/
│   ├── SKILL.md
│   └── references/
│       ├── anti-patterns.md
│       ├── interpreting-failures.md
│       ├── property-catalog.md
│       └── property-driven-design.md
└── pbt-hypothesis/
    ├── SKILL.md
    └── references/
        ├── settings.md
        ├── stateful.md
        └── strategies.md
```

## Contributing

Library-specific companion skills (`pbt-fast-check`, `pbt-proptest`, `pbt-quickcheck`, …) are welcome. Add a new folder under `skills/`, follow the same `SKILL.md` + `references/` shape, and append the path to the `skills` array in `.claude-plugin/marketplace.json`.
